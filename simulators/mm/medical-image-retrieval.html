[Case Study] 의료 영상 자료 검색 모형 시뮬레이터

VQA-RAD 방사선 영상으로 CLIP 제로샷 분류, CLIP 임베딩 + 코사인 유사도 검색(텍스트→영상, 영상→영상), BLIP 캡셔닝과 시각 질의응답(VQA)을 따라갑니다. 대형 모형의 출력은 "모의 출력"으로, 코사인·softmax·검색 지표는 화면에서 직접 계산합니다.

문제 정의: 판독문으로 영상을 찾고, 영상으로 문장을 만든다

실습 노트북의 흐름

의료 데이터는 본질적으로 멀티모달입니다. 영상(X-ray / CT / MRI) + 판독문(텍스트) + 검사 수치(정형) + 진료 기록. 영상의학과 전문의가 영상을 "보고" 판독문을 "쓰는" 일은 이미지 → 텍스트 변환이고, 판독문으로 유사 증례 영상을 찾는 일은 텍스트 → 이미지 검색입니다.

Dual Encoder (CLIP)

이미지 인코더와 텍스트 인코더가 각각 벡터를 만들고 같은 벡터 공간에서 비교합니다. 제로샷 분류 / 이미지-텍스트 검색.

Encoder-Decoder (BLIP)

이미지 인코더가 만든 벡터를 텍스트 디코더가 받아 문장을 생성(GPT 방식)합니다. 이미지 캡셔닝 / 시각 질의응답(VQA).

Vision Encoder + LLM

LLaVA / MedGemma처럼 대형 언어 모델에 이미지 인코더를 연결해 대화형 판독을 보조합니다. 모델이 크고 GPU가 필요해 개념만 소개합니다.

데이터: VQA-RAD

flaviagiammarino/vqa-rad · 라이선스 CC0

방사선 영상(X-ray / CT / MRI) + 질문 + 답변으로 구성된 의료 시각 질의응답 데이터입니다. 실습 노트북은 Test 데이터만 사용하고, 같은 영상에 질문이 여러 개 달려 있어 영상 픽셀값의 해시로 중복을 제거합니다.

    의료 제로샷의 한계: 영상 종류 vs 소견 수준
    모의 갤러리 전체 · 정확도는 실제 계산
    
      
    영상 종류(X-ray / CT / MRI) 구분은 영상의 전체 모양이 확연히 달라 쉽고, 소견(정상 / 폐렴 / 흉수 / 심비대) 구분은 영상 안의 미세한 차이를 봐야 해 어렵습니다. 현재 문장 틀로 갤러리 전체를 분류한 결과입니다.
    
      
    
      
    
      
    사전 학습 데이터에 소견 설명이 충분하지 않으면 제로샷으로는 한계가 있습니다 → 의료 데이터로 Fine-Tuning이 필요합니다. 실습 노트북도 PubMedCLIP이 흉부 X선으로 분류한 영상 4장을 골라 소견 후보(문장 틀 '{}')로 비교했습니다.

    한계
    실습 노트북의 정리
    
      
    
        
    소견 수준 제로샷의 한계. 영상 종류 구분은 쉽지만, 정상 / 폐렴 / 흉수 / 심비대처럼 미세한 차이는 사전 학습 데이터에 소견 설명이 충분하지 않으면 제로샷으로 맞히기 어렵습니다 → Fine-Tuning 필요.
    
        
    일반 모형은 의료 소견을 모릅니다. 일반 캡셔닝 모형은 "흑백 사진", "사람의 가슴" 수준의 묘사는 하지만 의학적 소견은 만들지 못합니다(인터넷 이미지 위주 사전 학습). 일반 VQA는 test[0] 영상의 장기를 stomach라고 답했습니다 → 도메인 사전 학습 / Fine-Tuning 필요.
    
        
    환각 (Hallucination). 생성 모형은 영상에 없는 병변을 그럴듯한 문장으로 만들어 낼 수 있습니다. 임상에서는 반드시 판독의(전문의)가 검토합니다.
    
        
    대부분 영어로 학습. 한국어 질문·판독문에는 추가 학습이 필요합니다. 검색 탭에서 한국어로 검색하면 모의 인코더도 개념을 약하게만 반영합니다.
    
        
    커뮤니티 공개 모형 주의. 모델 카드에 학습 데이터·평가 정보가 충분하지 않을 수 있고, Test 데이터가 학습에 포함되었을 가능성도 있습니다. 로드 보고서(MISSING / UNEXPECTED)와 출력이 비어 있지 않은지 먼저 확인합니다(노트북: Fine-Tuning 모형 빈 출력 → 정확도 0.0).
